# 两站首屏可用与性能优化设计

日期：2026-08-09  
适用仓库：`ymirtool-website`、`paperfixes`

## 1. 背景与证据

YmirTool 的核心工具页当前先输出空的 `#ymir-vue-tool-app`，随后再下载并执行约 1.56 MB JavaScript，其中包含完整 Vue 与 Element Plus；页面还会加载约 586 KB 的合并样式。工具本身虽然位于 DOM 顶部，但在框架挂载前没有真实输入控件，因此“页面已打开”和“工具可使用”之间存在明显等待。

YmirTool 首页已经静态输出搜索框与核心工具入口，但没有可直接运行的工具；同时首页为目录功能提前加载约 200 KB 的完整工具清单。用户到达首页后仍需选择并打开第二个页面才能完成任务。

PaperFix 当前 Vite 构建只有一个约 407 KB 的 JavaScript 首包。首页改写器、博客全文、后台、个人中心、定价页和多个弹窗被同步打入同一个入口，因此用户只想粘贴文本时仍需解析全部页面代码。

## 2. 目标

1. YmirTool 首页第一屏直接出现可运行的 JSON 格式化工具，不需要先打开工具目录。
2. YmirTool 八个重点工具页面在初始 HTML 中拥有完整输入、输出与操作控件，不再等待空容器挂载。
3. 八个重点工具不加载完整 Vue、Element Plus、全量工具清单和 586 KB 的历史合并样式。
4. PaperFix 首页改写器保持同步入口，非首页路由、博客全文和条件式组件拆分为独立代码块。
5. 不改变 PaperFix 的认证、套餐、30 天有效期、历史记录、数据库、支付、退款或 API 行为。
6. 保留两站现有公开 URL、核心 SEO 正文与移动端能力。

## 3. 非目标与诚实边界

- 本轮不重写 YmirTool 其余 142 个历史工具。它们继续使用现有兼容运行时，避免在没有逐项验收的情况下宣称已经轻量化。
- 本轮不把 PaperFix 改造成 SSR/SSG，也不处理全部技术 SEO 问题。
- 不使用只有视觉效果的骨架屏冒充“工具已可用”。YmirTool 快速工作台必须拥有真实事件处理和真实结果输出。
- 不调整广告、收费金额、免费次数和数据保留规则。

## 4. 方案选择

### 方案 A：只增加预加载与骨架屏

改动最小，但仍需下载和解析现有大包，改善主要是视觉上的，不能满足“第一眼即可使用”。不采用。

### 方案 B：原生快速工具层与 PaperFix 路由分包

为 YmirTool 八个重点工具建立无框架的轻量运行时；工具 HTML 由静态配置生成并直接输出。PaperFix 保留首页改写器为同步依赖，其他代码按需要加载。该方案直接消除主要首屏开销，且不触碰业务后端。采用此方案。

### 方案 C：重写全部工具并让 PaperFix 服务端渲染

长期架构最统一，但涉及 150 个工具、部署架构和 SEO 渲染链路，不能在当前优化中快速且可信地完成。不采用。

## 5. YmirTool 架构设计

### 5.1 轻量核心层

新增一个版本化的轻量核心脚本和一份精简样式。脚本由两层组成：

- **纯工具引擎**：JSON、Base64、URL 编解码、JavaScript 基础格式化、正则测试、文本对比、字数统计和 Unix 时间转换。纯函数不读取 DOM，便于单元测试。
- **工作台控制器**：读取页面的 `data-fast-tool` 配置，绑定输入、按钮、结果、复制、清空和示例操作。控制器只增强已经存在的 HTML，不负责生成首屏主体。

八个重点工具为：

1. `/json/`
2. `/base64/`
3. `/urlencode/`
4. `/formatjs/`
5. `/regex/`
6. `/textdiff/`
7. `/txtcount/`
8. `/unixtime/`

这些页面不再引用 `ymir-tool-runtime-v63.js`、`ymir-tool-core-runtime-v63.js`、`ymir-vue-tools-app.js` 和 `ymir-tool-bundle-v65.css`。页面保留 shell、SEO 内容和相关链接，但工作台所需样式只来自精简样式文件。

### 5.2 初始 HTML 与视觉顺序

工具页面首个主要区块直接包含：标题、简短用途、输入控件、主要操作、结果控件、状态区、复制和清空操作。即使脚本尚未执行，用户也能立即看到、聚焦和输入；脚本执行后立即运行本地操作。

首页在顶部导航之后、长篇营销说明之前加入“快速工作台”。默认工具为 JSON 格式化，旁边提供其他七个重点工具的直接入口。首页不复制完整八套逻辑，只复用同一个 JSON 引擎与控制器。

首页现有标题和价值说明保留，但缩短首屏占用并移动到快速工作台之后。核心工具卡与完整目录继续作为发现入口，而不是完成任务前的强制步骤。

### 5.3 加载顺序

1. 浏览器接收静态 HTML 与精简关键样式。
2. 输入框、按钮和输出框立即进入布局。
3. 轻量核心脚本以 `defer` 执行并绑定事件。
4. 完整工具清单只在用户聚焦搜索框、打开目录，或浏览器空闲时加载。
5. 收藏、最近使用、全站搜索和其他增强功能在工作台可用后初始化。

工具运行不发起网络请求，输入与结果不写入网络层。现有主题和语言逻辑可以保留，但不得阻塞工作台绑定。

### 5.4 状态与错误处理

- 输入无效时必须清空旧结果并显示就地错误，避免用户复制上一次成功结果。
- 复制失败时保留结果并给出明确提示。
- Base64、URL 和时间输入的边界错误必须返回可理解的错误文本。
- 正则表达式构造失败时不得执行匹配。
- JavaScript 格式化继续明确为“基础格式整理”，不扩大能力承诺。
- 如果增强脚本加载失败，页面不得显示永久转圈；输入控件保持可见，并显示重试提示。

### 5.5 生成与防漂移

新增确定性的页面更新脚本，根据八个工具配置更新首页和工具页工作台。生成器必须可重复执行，第二次运行不产生额外差异。验证脚本检查：

- 八页均有真实表单控件；
- 八页不再引用历史大包；
- 首页快速工作台位于营销长文之前；
- canonical、结构化数据和原有正文仍存在；
- 其他 142 页未被误改。

## 6. PaperFix 架构设计

### 6.1 首包边界

根路由 `/` 的 `ReducePage` 保持静态导入，确保文本框不经过路由懒加载。以下内容改为动态导入：

- `/home`、`/pricing`、`/examples`、`/faq`、`/privacy`、`/terms`
- `/blog`、`/blog/:slug`
- `/dashboard`、`/admin`、`/payment/done`
- 登录弹窗和仅处理阶段使用的 `JobPoller`

路由切换使用轻量、可访问的加载提示；根路由不得被 `Suspense` 回退覆盖。

### 6.2 博客与 SEO 数据

当前 SEO 组件经 `articleSlugs.ts` 间接导入全部博客正文，使全文进入首页依赖图。新增轻量文章元数据模块，只包含公开 slug、标题、描述、更新时间和生成结构化数据所需的最小字段。博客正文仅由博客路由块加载。

未知路由仍需获得明确页面内容，不能因为拆包出现空白页面。本轮不承诺改变 Vercel 的 HTTP 状态码策略。

### 6.3 条件组件预取

登录弹窗第一次需要时动态加载。桌面登录按钮和移动端登录按钮在 `pointerenter`、`focus` 或触摸意图出现时预取弹窗代码，减少点击后的等待。任务轮询器在提交开始时加载，不进入初始编辑器包。

套餐字符上限继续使用本地默认值即时渲染，后台配置请求只做异步校正，不能阻塞文本输入。

### 6.4 业务与安全不变量

- Cookie 会话、同源请求、短信限制与安全响应头保持不变。
- 原文和结果继续写入数据库并可在历史记录中查看。
- 付费套餐仍为 30 天，在当前剩余有效期之后叠加。
- 套餐过期后额度清零并恢复免费套餐。
- 支付事务、幂等结算和并发退款逻辑不改动。

## 7. 性能预算

性能预算同时采用确定性的资源大小和浏览器实测：

| 项目 | 预算 |
| --- | --- |
| YmirTool 首页及八个重点工具的首屏自有 JavaScript | 原始体积小于 100 KB |
| YmirTool 首页及八个重点工具的首屏关键 CSS | 原始体积小于 100 KB |
| YmirTool 工作台初始结构 | HTML 中存在，不允许空挂载容器 |
| PaperFix 根入口 JavaScript | 原始体积小于 250 KB |
| PaperFix 博客全文 | 不得出现在根入口块 |
| 移动端布局偏移 | CLS 保持接近 0 |

浏览器计时受到网络和设备影响，因此以前后同环境对比为主。目标是在移动端节流环境中让 YmirTool 工作台可交互时间和 LCP 明显下降，并让 PaperFix 首页首包至少减少 35%。

## 8. 测试设计

实现遵循测试先行：

1. 为八个纯工具引擎编写 Node 单元测试，先验证测试在实现前失败。
2. 为 YmirTool 页面结构编写回归测试，确认真实控件存在且历史大包引用消失。
3. 为首页编写顺序测试，确认快速工作台先于营销正文。
4. 为 PaperFix 编写入口依赖与懒加载策略测试，并用 Vite 构建产物验证分块。
5. 执行两站现有完整测试、类型检查、SEO 校验和构建。
6. 使用同一浏览器环境分别记录优化前后资源、FCP、LCP、DOM Interactive 与工具交互结果。
7. 手工验证八个 YmirTool 工具的示例、错误、复制与清空；验证 PaperFix 首页输入、登录、提交前校验和路由跳转。

## 9. 发布与回滚

两个仓库分别提交，避免一个站的问题阻塞另一个站回滚。先完成本地测试与前后基准，再部署预览环境验证；未获得生产发布指令前不直接部署生产。

YmirTool 回滚只需恢复八页和首页的资源引用；历史工具不受影响。PaperFix 回滚只需恢复同步导入，后端和数据库无需回滚。

## 10. 验收结论定义

只有同时满足以下条件才算完成：

- YmirTool 首页和八个重点工具的真实工作台在首屏 HTML 中存在并可实际运行；
- 八页已移除历史大包且通过全部功能验证；
- PaperFix 根入口完成分包并达到体积预算；
- 两站完整测试与构建通过；
- 浏览器实测证明首屏资源和交互等待下降；
- 没有更改明确列出的业务与安全不变量。
